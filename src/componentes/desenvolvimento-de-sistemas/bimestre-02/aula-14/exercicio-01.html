Enunciado

Quando criamos um objeto no mundo real, muitas vezes ele não pode existir sem certas informações fundamentais. Por exemplo, não faz sentido emitir uma passagem aérea sem o nome do passageiro e o número do voo. Se permitirmos que o objeto seja criado "vazio" para ser preenchido depois, corremos o risco de gerar dados inconsistentes no sistema.

Os Construtores servem justamente para garantir que um objeto nasça com os dados obrigatórios já validados. Além disso, quando os parâmetros do construtor têm o mesmo nome dos atributos da classe, utilizamos a palavra-chave this para guiar o Java sobre quem é a variável local e quem é o atributo da instância.

Nesta atividade, você vai corrigir um sistema de bilhete aérea que está permitindo a criação de passagens fantasmas (sem dados) e aplicar construtores em cadeia com uma interface Swing.

⚙️ Preparação

  1. Abra a sua IDE (Eclipse, IntelliJ ou VS Code).
  2. Crie um novo projeto Java.
  3. Crie um arquivo chamado EmissorPassagem.java.
  4. Cole o Código Base abaixo dentro do arquivo.

💻 Código Base

(Entregue este código para os alunos. Ele possui a interface pronta, mas a classe Bilhete está vulnerável pois usa o construtor padrão vazio do Java, permitindo objetos inválidos).

import javax.swing.*;
import java.awt.FlowLayout;

// ==========================================
// CLASSE BILHETE (ALUNO DEVERÁ MODIFICAR)
// ==========================================
class Bilhete {
    public String nomePassageiro;
    public String numeroVoo;
    public double precoAssento;

    // Atualmente não há construtores definidos. 
    // O Java usa o construtor padrão vazio: Bilhete()
}

// ==========================================
// INTERFACE GRÁFICA (PRONTA)
// ==========================================
public class EmissorPassagem extends JFrame {
    public EmissorPassagem() {
        super("Decolar - Emissor de Bilhetes");
        setLayout(new FlowLayout());

        JTextField txtNome = new JTextField(12);
        JTextField txtVoo = new JTextField(6);
        JButton btnEmitirPadrao = new JButton("Voo Promocional (Assento 1A)");
        JButton btnEmitirCustomizado = new JButton("Emitir Completo");

        btnEmitirCustomizado.addActionListener(e -> {
            // MODO VULNERÁVEL ATUAL: Criando objeto vazio e preenchendo depois
            Bilhete b = new Bilhete();
            b.nomePassageiro = txtNome.getText();
            b.numeroVoo = txtVoo.getText();
            b.precoAssento = 450.00;

            JOptionPane.showMessageDialog(this, "Bilhete Criado:\n" + 
                "Passageiro: " + b.nomePassageiro + "\nVoo: " + b.numeroVoo);
        });

        btnEmitirPadrao.addActionListener(e -> {
            // MODO ATUAL: Exige preenchimento manual repetitivo
            Bilhete bPromo = new Bilhete();
            bPromo.nomePassageiro = "PASSARELA PROMO";
            bPromo.numeroVoo = "AB123";
            bPromo.precoAssento = 150.00;

            JOptionPane.showMessageDialog(this, "Bilhete Promocional Emitido!");
        });

        add(new JLabel("Passageiro:")); add(txtNome);
        add(new JLabel("Voo:")); add(txtVoo);
        add(btnEmitirCustomizado); add(btnEmitirPadrao);

        setSize(350, 180);
        setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        setLocationRelativeTo(null);
    }

    public static void main(String[] args) {
        new EmissorPassagem().setVisible(true);
    }
}

🚀 O Desafio (Atividade em questão)

Sua missão é blindar a classe Bilhete usando construtores e a referência this. Siga os passos:

  • Modificadores de Acesso: Altere a visibilidade dos atributos nomePassageiro, numeroVoo e precoAssento de public para private. Crie apenas os métodos Getters para eles.
  • Construtor Principal (Tratando Ambiguidade com this):
    • Crie um construtor que obrigue o recebimento dos três parâmetros: public Bilhete(String nomePassageiro, String numeroVoo, double precoAssento).
    • Repare que os parâmetros têm o mesmo nome dos atributos. Use a palavra-chave this obrigatoriamente para assinalar os atributos da classe (ex: this.nomePassageiro = nomePassageiro;).
  • Construtor em Cadeia (this()):
    • Imagine que a empresa aérea lançou um voo promocional padrão (Voo: "PROMO99", Preço: 99.90).
    • Crie um segundo construtor que receba apenas o nome do passageiro: public Bilhete(String nomePassageiro).
    • Dentro deste construtor, use a palavra-chave this(...) na primeira linha para chamar o construtor principal, passando o nome recebido, o voo fixo "PROMO99" e o preço fixo 99.90.
  • Refatoração do Swing:
    • No botão btnEmitirCustomizado, altere o código para instanciar o objeto passando os dados coletados da tela diretamente dentro dos parênteses do new Bilhete(...).
    • No botão btnEmitirPadrao, altere o código para usar o seu segundo construtor, passando apenas o nome digitado na tela.

🏁 Orientações Finais

  • O que será avaliado:
    • Uso correto de this.atributo = parametro para resolver o conflito de escopo.
    • Implementação do construtor em cadeia utilizando this(...) corretamente na primeira linha do construtor secundário.
    • Eliminação de atribuições diretas (ex: b.nome = ...) na classe que gerencia a tela.
  • Dica Importante: Assim que você criar o primeiro construtor na classe Bilhete, o Java desativará automaticamente o construtor padrão vazio. Isso fará com que as linhas new Bilhete() no Swing fiquem vermelhas (erro de compilação). É exatamente esse o objetivo: forçar o programa a só criar o objeto se fornecer os dados!
