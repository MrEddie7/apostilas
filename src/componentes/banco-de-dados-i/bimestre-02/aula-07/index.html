Teoria & Conceitos

1. O que é o Dicionário de Dados?

O Dicionário de Dados é um repositório que contém os metadados (dados sobre os dados) de um banco de dados. Ele atua como uma "ponte" entre os usuários e os dados reais, registrando formalmente o que cada informação significa e como ela deve ser armazenada.

  • Finalidade: Prover um contexto para a definição e o registro de todos os elementos que formam a base de dados (tabelas, colunas, índices e restrições).
  • Transparência: Para o usuário final, o dicionário é muitas vezes invisível, mas ele é consultado pelo SGBD sempre que uma operação de consulta ou manipulação é solicitada para validar permissões e tipos de dados.

2. Metadados: O Coração da Documentação

Diferente dos dados operacionais (como o nome de um cliente específico), os metadados descrevem a intenção (esquema) do banco de dados. O dicionário deve documentar:

  • Nomes das Tabelas (Relações): Identificação única de cada assunto no banco.
  • Atributos (Colunas): Nomes, tipos físicos (integer, varchar, date) e tamanhos dos campos.
  • Restrições de Integridade: Definição de Chaves Primárias (PK), Chaves Estrangeiras (FK) e regras de unicidade.
  • Regras de Negócio e Validações: Instruções que restringem os valores aceitáveis para evitar anomalias.

3. Documentando Domínios e Restrições

O Domínio representa o conjunto de valores atômicos admissíveis para uma coluna. Documentar o domínio no dicionário de dados é vital para garantir que as comparações em consultas tenham sentido e que os dados inseridos sejam válidos.

Exemplos de Documentação de Domínios:

Atributo Domínio (Conjunto de Valores) Tipo/Formato
Sexo {'M', 'F'} CHAR(1)
Idade 16 ≤ idade ≤ 70 INTEGER
CPF Conjunto de 11 dígitos numéricos CHAR(11)
Salário Valores decimais positivos DECIMAL(10,2)

4. Implementação Prática via DDL

A montagem do dicionário de dados no SGBD é realizada através da Linguagem de Definição de Dados (DDL). Quando executamos comandos como CREATE TABLE, o SGBD compila essas instruções e as armazena no catálogo (dicionário físico).

Exemplo de Documentação em Código (SQL):

-- Criando a estrutura no dicionário de dados
CREATE TABLE Empregado (
    codigo_empregado INTEGER NOT NULL, -- PK: Não nulo e Único
    nome             CHAR(35) NULL,
    salario          DECIMAL(10,2) CHECK (salario > 0), -- Regra de Domínio
    PRIMARY KEY (codigo_empregado)
);

-- Adicionando uma restrição de integridade referencial
ALTER TABLE Empregado 
ADD CONSTRAINT FK_Departamento 
FOREIGN KEY (codigo_depto) REFERENCES Departamento(codigo_depto);

6. Checklist de Documentação

Para que um dicionário de dados seja completo, o analista deve verificar os seguintes pontos ao converter o modelo lógico em físico:

  • Opção de Nulo: Definir se a coluna aceita valores desconhecidos (NULL) ou se o preenchimento é obrigatório (NOT NULL).
  • Regras de Validação: Expressões que estabelecem intervalos (ex: NumItens >= 5 AND NumItens <= 15).
  • Chaves Substitutas: Documentar se a PK é uma chave natural do negócio ou uma chave artificial (ID numérico gerado pelo sistema).
  • Descrições Semânticas: Explicar o significado de cada atributo para que usuários e desenvolvedores interpretem os dados da mesma forma.
