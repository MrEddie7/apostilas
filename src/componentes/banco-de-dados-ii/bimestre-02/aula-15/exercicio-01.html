1. Enunciado

O departamento de Business Intelligence (BI) da plataforma ArenaStream solicitou uma série de relatórios estratégicos de auditoria para identificar falhas operacionais e comportamentos de engajamento na plataforma. Como engenheiro de dados, sua missão é construir consultas SQL otimizadas utilizando exclusivamente o conceito de Subqueries para extrair essas informações com o menor custo de processamento possível no servidor.

2. Preparação do Ambiente

Antes de iniciar o desenvolvimento dos scripts de auditoria, certifique-se de que a sua estação de trabalho atende a todos os requisitos técnicos listados abaixo:

  • SGBD Instalado: É necessário possuir o servidor MySQL (versão 8.0 ou superior) instalado, configurado e em plena execução local (localhost).
  • Ferramenta Visual (Interface Gráfica): Tenha à disposição um cliente ou ferramenta de manipulação visual de banco de dados, como o MySQL Workbench, DBeaver, Beekeeper Studio ou VS Code com extensões SQL, para facilitar a escrita das queries e a visualização das tabelas de resultados.
  • Base de Dados Dedicada: Para evitar conflitos de chaves estrangeiras com laboratórios anteriores, crie e selecione um esquema limpo executando os comandos: CREATE DATABASE IF NOT EXISTS arenastream_auditoria; seguido de USE arenastream_auditoria;.
  • Conhecimento Prévio Requerido: O aluno deve dominar a sintaxe básica de projeção (SELECT), filtragem simples (WHERE), chaves primárias e estrangeiras, além de compreender o conceito teórico de consultas aninhadas (subconsultas) e operadores booleanos de conjunto.

3. Código Base (Estrutura e Dados)

Para isolar esta atividade prática dos laboratórios anteriores, utilizaremos um banco de dados dedicado chamado arenastream_auditoria. Certifique-se de executar o bloco abaixo para garantir que o esquema de tabelas esteja limpo e pronto para os testes:

Preparação Inicial

CREATE DATABASE IF NOT EXISTS arenastream_auditoria;
USE arenastream_auditoria;

SET FOREIGN_KEY_CHECKS = 0;
DROP TABLE IF EXISTS patrocinadores;
DROP TABLE IF EXISTS equipes;
DROP TABLE IF EXISTS pro_players;
SET FOREIGN_KEY_CHECKS = 1;

Criação E Inserção

Execute o script abaixo para criar as tabelas de infraestrutura de e-sports da plataforma e carregar a massa de dados de teste:

-- Tabela A: Equipes de E-sports cadastradas na liga
CREATE TABLE equipes (
    id INT PRIMARY KEY AUTO_INCREMENT,
    nome_equipe VARCHAR(50) NOT NULL,
    divisao VARCHAR(20) NOT NULL
);

-- Tabela B: Pro-players e seus respectivos salários e vínculos
CREATE TABLE pro_players (
    id INT PRIMARY KEY AUTO_INCREMENT,
    id_equipe INT,
    nickname VARCHAR(50) NOT NULL,
    salario DECIMAL(10,2) NOT NULL,
    posicao VARCHAR(30) NOT NULL,
    FOREIGN KEY (id_equipe) REFERENCES equipes(id)
);

-- Tabela C: Patrocinadores e o investimento injetado diretamente nas equipes
CREATE TABLE patrocinadores (
    id INT PRIMARY KEY AUTO_INCREMENT,
    id_equipe INT,
    nome_empresa VARCHAR(50) NOT NULL,
    valor_patrocinio DECIMAL(12,2) NOT NULL,
    FOREIGN KEY (id_equipe) REFERENCES equipes(id)
);

4. O Desafio (Questões Práticas)

Com o banco de dados devidamente povoado, você deve construir os scripts SQL para extrair as respostas das 4 demandas de auditoria abaixo. Regra Obrigatória: É proibido o uso de INNER JOIN ou LEFT JOIN globais nas cláusulas principais; resolva as amarrações utilizando subqueries.

Questão 1: Média Salarial de Elite (Subquery Independente)

A diretoria financeira quer uma lista com o nickname e o salário de todos os pro-players que ganham um salário estritamente acima da média salarial geral de todos os jogadores cadastrados no banco de dados.

Questão 2: Disparidade por Divisão (Subquery Correlacionada)

Para identificar anomalias na folha de pagamento, liste o nickname, o salário e o ID da equipe dos pro-players que recebem um salário maior do que a média salarial específica da equipe à qual eles pertencem.

Questão 3: Auditoria de Marketing (Operador EXISTS)

O setor de parcerias comerciais precisa listar o nome de todas as equipes da liga que possuem pelo menos um patrocinador ativo injetando capital, ocultando as marcas que correm o campeonato sem apoio financeiro.

Questão 4: Alerta de Inatividade Operacional (Operador NOT EXISTS)

O comitê organizador do torneio precisa aplicar uma penalidade para as organizações que se inscreveram mas não montaram time. Liste o nome de todas as equipes que não possuem nenhum jogador vinculado a elas.

5. Orientações Finais

  • Fique atento aos apelidos das tabelas (C, P, E) para não misturar os escopos nas subqueries correlacionadas.
  • Lembre-se de que o operador EXISTS não se importa com as colunas do SELECT interno; utilize o padrão técnico SELECT 1 para garantir legibilidade de código.
  • Valide os resultados visualmente com base na tabela física: na Questão 4, por exemplo, a única equipe impressa na tela deve ser a EquipeSemPlayer.
