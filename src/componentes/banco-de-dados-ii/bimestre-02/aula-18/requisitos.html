Para que o banco de dados seja considerado homologável, a estrutura física, lógica e de segurança deve dar suporte direto às regras e requisitos listados abaixo.

A. Requisitos de Negócio (RN)

As regras macro que definem as premissas de conformidade e o valor estratégico do software.

  • RN01 - Controle Preventivo de Endividamento: O saldo acumulado da conta do assinante nunca poderá ficar negativo. O sistema de banco de dados deve ser planejado para impedir registros que invalidem a integridade financeira do fluxo de caixa.
  • RN02 - Classificação Rígida de Fluxo: Não são permitidos registros flutuantes ou genéricos de reprodução de mídia. Toda e qualquer ação de consumo deve estar estritamente vinculada a uma categoria rastreável para fins de auditoria e BI.
  • RN03 - Histórico Inalterável (Imutabilidade): Por motivos de auditoria fiscal de direitos autorais, os logs e históricos de reprodução gravados são definitivos. É terminantemente proibido o uso de comandos que apaguem ou editem o rastro histórico de visualizações de um perfil, mesmo que o vídeo em questão seja removido do catálogo ativo.

B. Requisitos Funcionais (RF)

O que o sistema deve ser capaz de fazer (funcionalidades analíticas e operacionais).

  • RF01 - Gestão Multiperfil (Contas Compartilhadas): O sistema deve permitir o isolamento de dados de preferência e histórico para até 5 perfis sob o cadastro de uma única conta de assinante titular.
  • RF02 - Rastreamento de Eventos (Logs de Reprodução): O sistema deve registrar de forma automática os metadados técnicos do momento em que o usuário inicia um conteúdo (endereço IP, tipo de dispositivo e carimbo de tempo).
  • RF03 - Painel Analítico "Continuar Assistindo": O sistema deve recuperar as sessões de reprodução pausadas de um perfil específico, priorizando os acessos mais recentes.
  • RF04 - Consolidação de Minutos por Produtora (Faturamento): O sistema deve calcular o tempo total consumido (em minutos ou horas) de todos os vídeos pertencentes a uma determinada produtora de conteúdo dentro de um período escolhido.
  • RF05 - Auditoria de Infraestrutura Regional: O sistema deve consolidar o volume de acessos segmentando os dados simultaneamente por localização geográfica (UF) do assinante e tipo de dispositivo de conexão.

C. Requisitos Não Funcionais (RNF)

Como o sistema deve se comportar (restrições técnicas, segurança, performance e arquitetura).

  • RNF01 - Padronização de Nomenclatura Relacional: Todas as tabelas físicas criadas no SGBD devem utilizar nomenclatura obrigatória no plural. Todas as chaves primárias devem adotar estritamente o identificador universal id.
  • RNF02 - Precisão Geométrica Numérica: Campos que envolvem valores financeiros (assinaturas) ou agregações matemáticas complexas de tempo não podem utilizar tipos de dados de precisão aproximada (ponto flutuante) devido ao risco de perda de centavos por arredondamento computacional.
  • RNF03 - Controle de Acesso Baseado em Papéis (RBAC): O banco de dados deve implementar privilégios de segurança distintos. A aplicação que interage com o usuário final não pode possuir privilégios de alteração de tabelas (DDL) ou acesso total aos logs históricos de auditoria.
  • RNF04 - Mascaramento de Dados Sensíveis (Conformidade LGPD): A infraestrutura deve garantir que analistas de marketing corporativo consigam extrair relatórios demográficos e estatísticos sem que tenham acesso visual direto a dados sensíveis dos usuários (como CPF, e-mail e nome real).
  • RNF05 - Otimização de Resposta (Tuning): Consultas de alta demanda na plataforma (como a montagem da tela inicial do usuário) não podem realizar varreduras completas em tabelas (Full Table Scan). O tempo de resposta para recuperação de índices de engajamento em bases de dados massivas deve ser medido em milissegundos.
