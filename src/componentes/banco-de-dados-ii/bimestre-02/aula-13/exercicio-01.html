1. Enunciado: Ecossistema de Vendas "TechStore Pro"

Para uma gestão eficiente, a TechStore Pro separou as informações de vendas em: Vendedores, Clientes, Pedidos, Produtos e Itens do Pedido. Essa normalização evita redundâncias e garante a integridade dos dados. O desafio agora é navegar por essa estrutura para obter relatórios que exijam a combinação de até quatro ou cinco tabelas simultaneamente.

Preparação

  • Ambiente: MySQL ou PostgreSQL.
  • Lembre-se: em junções de muitas tabelas, o uso de Aliases (apelidos como V, P, IP) é essencial para a legibilidade do código.
  • A ordem de criação das tabelas e inserção dos dados deve respeitar as Chaves Estrangeiras para evitar erros de restrição.

2. Código Base (Estrutura e Dados Reais)

Copie e execute o script abaixo para preparar seu ambiente de testes:

CREATE TABLE vendedores (
    id INT PRIMARY KEY,
    nome_vendedor VARCHAR(50),
    salario_fixo DECIMAL(10,2)
);

CREATE TABLE clientes (
    id INT PRIMARY KEY,
    nome_cliente VARCHAR(50),
    cidade VARCHAR(30),
    uf CHAR(2)
);

CREATE TABLE produtos (
    id INT PRIMARY KEY,
    descricao VARCHAR(50),
    unidade VARCHAR(5), -- Ajustado para suportar 'SACH'
    valor_unitario DECIMAL(10,2)
);

CREATE TABLE pedidos (
    id INT PRIMARY KEY,
    id_cliente INT,
    id_vendedor INT,
    prazo_entrega INT,
    FOREIGN KEY (id_cliente) REFERENCES clientes(id),
    FOREIGN KEY (id_vendedor) REFERENCES vendedores(id)
);

CREATE TABLE itens_pedidos (
    id_pedido INT,
    id_produto INT,
    quantidade INT,
    PRIMARY KEY (id_pedido, id_produto),
    FOREIGN KEY (id_pedido) REFERENCES pedidos(id),
    FOREIGN KEY (id_produto) REFERENCES produtos(id)
);

3. O Desafio (Atividade)

Escreva as consultas SQL para gerar os seguintes relatórios:

  1. Relatório Completo de Itens (Múltiplos Joins): Liste o número do pedido, o nome do cliente, o nome do vendedor, a descrição do produto e a quantidade. (Dica: Você precisará juntar as 5 tabelas).
  2. Produtos sem Saída (LEFT JOIN): Liste todos os produtos da loja e a quantidade vendida. Produtos que nunca foram vendidos devem aparecer com quantidade NULL ou zero.
  3. Faturamento por Vendedor (Joins + Agregação): Calcule o valor total vendido por cada vendedor (Quantidade * Valor Unitário). Considere apenas vendedores que realizaram vendas.
  4. Clientes Órfãos (RIGHT JOIN): Liste todos os clientes e seus pedidos. Filtre para exibir apenas os clientes que não realizaram nenhum pedido até o momento.
  5. Cruzamento de Localidade (SELF JOIN): Utilizando apenas a tabela Cliente, liste pares de nomes de clientes que moram na mesma cidade (Ex: "Cliente A e Cliente B moram em RJ").

Orientações Finais

  • Ambiguidade: Sempre que selecionar o id de uma tabela que é chave estrangeira em outra, use o prefixo (ex: Vendedor.id_vendedor) para o banco não se confundir.
  • Distinct: Se um vendedor aparecer várias vezes em uma lista onde você quer apenas nomes únicos, use SELECT DISTINCT.
  • Tratamento de Nulos: Em relatórios de BI, campos NULL em Outer Joins podem ser tratados com funções como IFNULL (MySQL) ou COALESCE para exibir "0" ou "Sem Vendas".
  • Cláusula USING: Se as colunas de ligação tiverem o mesmo nome em ambas as tabelas (como id_pedido), você pode simplificar o join usando JOIN ... USING (id_pedido).
