Teoria & Conceitos

Esta aula aborda as Funções de Agregação, ferramentas essenciais para transformar grandes volumes de dados em informações gerenciais e estatísticas. Ao contrário das operações que atuam linha a linha, as funções de agregação operam sobre conjuntos de valores (tuplas) para retornar um único valor resultante.

1. Fundamentos e a Álgebra Relacional

Na teoria relacional, as funções de agregação não faziam parte do modelo original, sendo introduzidas posteriormente através do operador ℑ (Gótico I).

  • Lógica: O operador recebe atributos de agrupamento e uma lista de funções aplicadas a colunas específicas.
  • Fechamento: O resultado de uma agregação é sempre uma nova relação (tabela), mesmo que contenha apenas uma linha e uma coluna.

2. As Funções Fundamentais

A. COUNT (Contagem)

Existem duas formas cruciais de utilizar o COUNT, e a diferença entre elas é um dos pontos onde mais ocorrem erros:

  • COUNT(*): Conta todas as linhas do conjunto resultante, incluindo linhas com valores nulos ou duplicados.
  • COUNT(coluna): Conta apenas as linhas onde a coluna especificada não é nula.
-- Exemplo: Quantos vendedores ganham acima de 2.500?
SELECT COUNT(*) AS total_vendedores 
FROM vendedores 
WHERE salario_fixo > 2500;

B. SUM (Soma) e AVG (Média)

Ambas operam exclusivamente sobre valores numéricos. Elas ignoram valores nulos no cálculo.

Dica Avançada: Se você precisar somar tempos (tipo TIME), deve convertê-los para segundos (TIME_TO_SEC), somar e converter de volta (SEC_TO_TIME).

-- Exemplo: Média salarial e total da folha de pagamento
SELECT AVG(salario_fixo) AS media_salarial, SUM(salario_fixo) AS total_folha
FROM vendedores;

C. MAX (Máximo) e MIN (Mínimo)

Identificam os valores extremos em um conjunto. Podem ser aplicadas a números, datas e até strings (seguindo a ordem alfabética/colação).

-- Exemplo: Menor e maior salário da tabela
SELECT MIN(salario_fixo) AS menor_salario, MAX(salario_fixo) AS maior_salario 
FROM vendedores;

3. Agrupamento: O Poder do GROUP BY

O GROUP BY organiza o resumo dos dados em grupos lógicos baseados em um ou mais atributos.

A "Armadilha" do Agrupamento: Ao usar GROUP BY, você só pode selecionar as colunas que estão presentes na cláusula GROUP BY ou colunas dentro de funções de agregação. Tentar selecionar uma coluna "solta" (como a data de uma venda máxima) retornará valores indeterminados ou erro, dependendo do SGBD.

-- Exemplo: Total de produtos vendidos por pedido
SELECT numero_pedido, COUNT(*) AS total_itens
FROM item_de_pedido 
GROUP BY numero_pedido;

4. Filtrando Agregados: A Cláusula HAVING

Muitos alunos confundem WHERE com HAVING. A regra é simples:

  • WHERE: Filtra as linhas antes da agregação ser processada.
  • HAVING: Filtra os grupos após a agregação ter sido calculada.
-- Exemplo: Listar apenas pedidos que possuem mais de 3 produtos
SELECT numero_pedido, COUNT(*) AS total_produtos
FROM item_de_pedido
GROUP BY numero_pedido
HAVING COUNT(*) > 3;

5. Tópicos Avançados

A. Tratamento de Nulos com Agregações

Como a maioria das funções ignora nulos, o resultado de um SUM ou AVG sobre uma coluna que só contém nulos será NULL (e não zero). Para relatórios limpos, use funções de tratamento:

  • MySQL: IFNULL(SUM(coluna), 0)
  • PostgreSQL/Universal: COALESCE(SUM(coluna), 0)

B. Identificação de Duplicatas

As funções de agregação são a forma mais eficiente de encontrar dados duplicados em uma tabela.

-- Identificar nomes de clientes repetidos
SELECT nome_cliente, COUNT(*) 
FROM cliente
GROUP BY nome_cliente
HAVING COUNT(*) > 1;

C. Totais e Subtotais (ROLLUP)

No MySQL, você pode gerar totais gerais e subtotais automaticamente adicionando WITH ROLLUP ao final do agrupamento.

-- Mostra contagem por usuário e um total geral no final (como uma linha com NULL)
SELECT srcuser, COUNT(*) 
FROM mail 
GROUP BY srcuser WITH ROLLUP;

D. Funções de Janela (Window Functions - PostgreSQL)

O PostgreSQL permite realizar agregações sem "colapsar" as linhas em grupos, usando a cláusula OVER(). Isso permite comparar uma linha individual com a média do grupo na mesma linha.

-- Exemplo PostgreSQL: Salário individual vs Média do departamento
SELECT nome, salario, AVG(salario) OVER(PARTITION BY depto_id) as media_depto
FROM empregados;

E. Ratio de Repetição

Um conceito avançado para analistas é o cálculo da repetitividade dos dados: COUNT(DISTINCT coluna) / COUNT(coluna).

  • Um valor próximo de 1 indica que quase todos os dados são únicos.
  • Um valor próximo de 0 indica alta repetição, o que significa que o GROUP BY será muito eficiente para categorizar esses dados.
Código de Demonstração

Exemplos de Código

1. Nível Básico: Resumos Globais

Neste nível, o banco olha para a tabela inteira como um único grupo.

  • COUNT: "Quantos produtos cadastrados nós temos?"
SELECT COUNT(*) AS total_produtos FROM produtos;
  • MAX e MIN: "Qual o preço do produto mais caro e do mais barato?"
SELECT MAX(valor_unitario), MIN(valor_unitario) FROM produtos;
  • SUM: "Qual o valor total de todos os salários fixos dos vendedores?"
SELECT SUM(salario_fixo) FROM vendedores;

2. Nível Intermediário: Agrupamento Simples (GROUP BY)

Aqui começamos a separar os dados em "baldes" antes de calcular.

  • COUNT com GROUP BY: "Quantos clientes temos em cada estado (UF)?"
SELECT uf, COUNT(id) 
FROM clientes 
GROUP BY uf;
  • AVG com GROUP BY: "Qual a média de quantidade de itens por pedido?"
SELECT id_pedido, AVG(quantidade) 
FROM itens_pedidos 
GROUP BY id_pedido;

3. Nível Avançado: Joins + Agregação + HAVING

Este é o cenário real de um Tech Lead: cruzar tabelas e filtrar os resultados após o cálculo.

Desafio: "Liste os vendedores que faturaram mais de R$ 500,00 no total."

Nota: Não podemos usar WHERE para o total, pois o total só existe após o agrupamento. Usamos o HAVING.

SELECT 
    v.nome_vendedor, 
    SUM(i.quantidade * pr.valor_unitario) AS faturamento_total
FROM vendedores v
INNER JOIN pedidos p ON v.id = p.id_vendedor
INNER JOIN itens_pedidos i ON p.id = i.id_pedido
INNER JOIN produtos pr ON i.id_produto = pr.id
GROUP BY v.id
HAVING faturamento_total > 500.00;

4. Nível Expert: Relatórios Complexos

Combinando tudo para encontrar padrões específicos.

Produtos mais vendidos em SP:

SELECT 
    pr.descricao, 
    SUM(i.quantidade) AS total_unidades
FROM produtos pr
INNER JOIN itens_pedidos i ON pr.id = i.id_produto
INNER JOIN pedidos p ON i.id_pedido = p.id
INNER JOIN clientes c ON p.id_cliente = c.id
WHERE c.uf = 'SP'
GROUP BY pr.id
ORDER BY total_unidades DESC;

Dicas & Lembretes

  • A Regra do "Esmagamento": Pense nas funções agregadoras como uma prensa hidráulica. Elas pegam 100 linhas e as esmagam em uma única linha de resultado.
  • O Porteiro (WHERE) vs. O Fiscal (HAVING):
    • O WHERE é o porteiro: ele decide quem entra na festa (antes da soma).
    • O HAVING é o fiscal: ele só olha para os grupos que já estão prontos e decide quem fica.
  • Identidade Visual: Se você deu um SELECT no nome_vendedor, você precisa dar um GROUP BY no nome_vendedor. Se esquecer, o SQL vai te dar um erro ou um resultado "mentiroso".
  • O Fantasma do NULL: Lembre-se que SUM e AVG são "alérgicos" ao NULL. Eles simplesmente pulam as linhas vazias como se elas não existissem.
  • Performance do COUNT: Se você só quer saber o total de linhas, use COUNT(*). O banco de dados é treinado para contar asteriscos muito mais rápido do que olhar coluna por coluna.
