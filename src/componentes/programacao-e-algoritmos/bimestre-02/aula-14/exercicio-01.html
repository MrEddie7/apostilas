Enunciado

Em sistemas de software do mundo real, muitas vezes precisamos que um conjunto de instruções seja executado repetidamente até que uma condição específica seja atingida. Estruturas de repetição como o while (pré-teste) e o do-while (pós-teste) eliminam a necessidade de duplicar linhas de código manualmente e são ideais para o tratamento de iterações indeterminadas, onde não sabemos previamente a quantidade exata de repetições.

Nesta atividade, você desenvolverá o esqueleto lógico de um Caixa Eletrônico (ATM) por meio do console. Você aplicará os conceitos de pós-teste para manter o menu principal ativo até que o usuário decida sair, e de pré-teste / valores sentinela para validar que operações críticas, como depósitos, não aceitem valores inconsistentes.

Preparação

  1. Abra a sua IDE de preferência (Eclipse, IntelliJ ou VS Code).
  2. Crie um novo projeto Java ou uma nova classe.
  3. Crie um arquivo chamado CaixaEletronico.java.
  4. Cole o Código Base fornecido abaixo dentro do arquivo.

Código Base

Este código contém a estrutura inicial do sistema. Note que as estruturas de repetição estão ausentes ou incompletas, fazendo com que o programa execute apenas uma vez e encerre abruptamente.

import java.util.Scanner;

public class CaixaEletronico {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        double saldo = 500.00; // Saldo inicial
        int opcao = 0;

        System.out.println("--- BEM-VINDO AO BANCO JAVA ---");

        // TODO: O menu abaixo deve rodar repetidamente usando do-while
        System.out.println("\n=== MENU PRINCIPAL ===");
        System.out.println("1 - Consultar Saldo");
        System.out.println("2 - Realizar Depósito");
        System.out.println("3 - Sair do Sistema");
        System.out.print("Escolha uma opção: ");
        opcao = scanner.nextInt();

        // Processa a opção selecionada
        switch (opcao) {
            case 1:
                System.out.println("-> Seu saldo atual é R$ " + saldo);
                break;
            case 2:
                System.out.print("Digite o valor do depósito: R$ ");
                double valorDeposito = scanner.nextDouble();
                
                // TODO: Validar usando um laço de repetição condicional
                saldo += valorDeposito;
                System.out.println("-> Depósito de R$ " + valorDeposito + " realizado com sucesso.");
                break;
            case 3:
                System.out.println("Encerrando o sistema... Até logo!");
                break;
            default:
                System.out.println("Opção inválida!");
        }

        // TODO: O programa não deve fechar o scanner até que o loop termine por completo
        scanner.close();
    }
}

O Desafio

Sua missão é refatorar o código base aplicando as estruturas de repetição adequadas para torná-lo um sistema funcional e resiliente a erros de entrada de dados:

1. Implementação do Menu Iterativo (do-while)

  • Envolva a exibição do menu principal e a estrutura switch/case dentro de um laço do-while.
  • O programa deve obrigatoriamente exibir o menu pelo menos uma vez. Ele deve continuar rodando e reexibindo as opções enquanto o usuário não digitar a opção 3 (Sair do Sistema).
  • Lembre-se da regra de sintaxe do pós-teste: use o ponto e vírgula (;) imediatamente após o fechamento dos parênteses da condição do while.

2. Validação de Entrada de Dados (while)

  • No case 2 (Realizar Depósito), implemente uma estrutura de pré-teste utilizando o comando while para garantir a integridade dos dados.
  • O caixa eletrônico não pode aceitar valores de depósito menores ou iguais a zero.
  • Se o usuário digitar um valor inválido (ex: -50.00 ou 0), o laço while deve travar o fluxo, exibir uma mensagem de erro ("Valor inválido! Tente novamente.") e solicitar que o usuário digite o valor novamente dentro do corpo do laço. O programa só deve prosseguir e atualizar a variável saldo quando o valor fornecido for estritamente positivo.

3. Garantia contra Loops Infinitos

  • Certifique-se de que a leitura do scanner para a nova tentativa de depósito aconteça dentro do corpo do while, garantindo a atualização da variável de controle e evitando que o sistema trave em um laço infinito.

Orientações Finais

  • O que será avaliado:
    • O uso correto do do-while para manter o menu ativo e sua respectiva terminação com ;.
    • O uso correto do while como mecanismo de pré-teste para impedir depósitos negativos ou zerados.
    • A modificação correta das variáveis de controle dentro de cada laço para evitar comportamentos infinitos indesejados.
  • Dica de Ouro: Teste o seu programa digitando opções inválidas no menu e valores negativos no depósito. O sistema deve ser capaz de rejeitar todas as entradas incorretas e se manter rodando de forma limpa até que o número 3 seja digitado.
  • Entrega: Envie o arquivo de código fonte CaixaEletronico.java devidamente identado, corrigido e testado.
