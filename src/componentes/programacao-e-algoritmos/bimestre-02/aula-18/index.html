Enunciado

Para consolidar o aprendizado sobre Estruturas de Controle em Java, seu desafio neste final de bimestre será desenvolver um jogo de Jokenpô (Pedra, Papel e Tesoura) baseado em linhas de comando no terminal.

O software deve conter flexibilidade para dois modos de jogo: contra o computador ou em modo cooperativo local contra um amigo. Além disso, a partida não deve terminar em uma jogada isolada. O sistema precisa gerenciar um modelo de Melhor de 3 rodadas, onde o primeiro participante a atingir duas vitórias consolidadas é declarado o vencedor do confronto.

Preparação

  1. Abra o seu ambiente de desenvolvimento integrado (IDE).
  2. Crie um novo arquivo ou classe Java com o nome de JokenpoMelhorDeTres.java.
  3. Utilize a estrutura do Código Base fornecido abaixo para iniciar o projeto.

O Desafio (Atividade em questão)

Construa a lógica completa do jogo respeitando os requisitos técnicos acumulados ao longo das aulas:

  • Laço Geral de Repetição (Jogar Novamente): Envolva toda a execução do jogo em uma estrutura de repetição que, ao final da declaração de um campeão, pergunte se o usuário deseja iniciar uma nova partida (Opção 1 - Sim, Opção 2 - Não). O programa só deve fechar se o usuário escolher sair.
  • Tratamento de Entradas Inválidas (Validação Estrita): Você deve impedir que o programa quebre ou continue com dados incorretos. Utilize laços condicionais para verificar as entradas do usuário:
    • No menu inicial e no menu de repetição, o programa deve travar e pedir o dado novamente se for digitado um valor diferente de 1 ou 2.
    • Durante a escolha de jogadas (Pedra, Papel ou Tesoura), o laço deve obrigar o usuário a redigitar caso o número fornecido não esteja estritamente entre 1 e 3.
  • Gerenciamento do Placar (Melhor de 3): Crie variáveis contadoras para monitorar as vitórias do Jogador 1 e do Inimigo (seja ele o computador ou o Jogador 2). O laço de rodadas deve persistir ativo enquanto nenhum dos dois alcançar a meta de 2 vitórias. Empates não somam pontos para nenhum lado e mantêm o placar estável.
  • IA do Computador (Modo 1): Caso a opção escolhida seja Single Player, configure o oponente para gerar um valor inteiro aleatório entre 1 e 3 usando as funções matemáticas de sorteio da linguagem Java.
  • Esconder Jogadas (Modo 2 - Multiplayer): No modo de dois jogadores no mesmo teclado, para manter o sigilo estratégico da escolha, aplique uma estrutura de repetição do tipo for para saltar múltiplas linhas em branco (cerca de 30 linhas) no terminal imediatamente após a entrada do Jogador 1. Isso empurrará o texto anterior para cima, impedindo que o Jogador 2 veja a opção escolhida.
  • Tabela-Verdade de Resultados: Utilize condicionais compostas com conectivos lógicos (E / OU) para agrupar todas as condições possíveis de vitória do Jogador 1 de forma limpa, tratando de forma genérica os cenários de empate e derrotas.

Orientações Finais

  • Critérios de Avaliação:
    • Presença obrigatória de validação de dados em todas as entradas capturadas do teclado para conter falhas do usuário.
    • Aplicação correta de contadores de rodada e acumuladores de pontuação para as vitórias.
    • Uso adequado e limpo dos conectivos lógicos na tomada de decisão sobre quem pontua a cada volta do laço.
    • Identidade visual estruturada do placar parcial exibida no console a cada final de turno.
  • Recomendação de Testes: Durante o desenvolvimento, force erros de digitação intencionais. Digite números negativos, opções inexistentes ou letras nos menus para garantir que suas estruturas de validação estão segurando o fluxo do console perfeitamente.
  • Entrega: Submeta o arquivo com a extensão .java limpo, devidamente indentado e livre de erros de compilação.
