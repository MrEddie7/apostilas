Teoria & Conceitos

Esta seção de Teoria & Conceitos para a Aula 16 foca no detalhamento dos componentes internos do Diagrama de Classes, o diagrama estrutural mais utilizado da UML. Ele descreve os tipos de objetos no sistema e seus relacionamentos estáticos, sendo capaz de explicitar detalhes de implementação essenciais para a codificação.

1. A Estrutura da Classe

Graficamente, uma classe é representada por um retângulo dividido em três compartimentos:

  • Superior: Contém o nome da classe (em negrito e centralizado).
  • Intermediário: Lista os atributos (características estruturais).
  • Inferior: Lista as operações ou métodos (comportamentos).

Nota: Compartimentos podem ser suprimidos para aumentar a legibilidade, mas isso não significa que estejam vazios.

2. Atributos (Estado)

Os atributos representam os dados que uma classe é capaz de armazenar, definindo o estado de cada objeto instanciado.

Sintaxe do Atributo

A forma completa de um atributo segue o padrão:

visibilidade /nome : tipo [multiplicidade] = valor_padrão {propriedades}
- /historicoTaxas : double [1..*] = 0.01 {ordered, unique}
  • Visibilidade (+, -, #, ~): Definida como protegida (protected), o que significa que o atributo é visível para a própria classe e suas subclasses (como Gerente ou Diretor).
  • Derivação (/): Um atributo marcado com uma barra (/) indica que ele é calculado a partir de outros dados e não precisa ser armazenado fisicamente (ex: /idade calculada a partir da dataNascimento).
  • Nome: Deve ser um substantivo ou frase curta, geralmente iniciando com letra minúscula (ex: dataNascimento).
  • Tipos de Dados: Podem ser tipos primitivos (int, double, boolean, String) ou outras classes definidas no sistema.
  • Multiplicidade: Entre colchetes [ ], indica quantos valores o atributo pode conter (ex: telefone: String [1..3]). O padrão é .
  • Valor Padrão: O valor inicial sugerido para a primeira entrada. 0.01 (1%) no exemplo acima.
  • Propriedades: Características adicionais, como {ordered} (os valores são mantidos em ordem) ou {unique} (os valores devem ser únicos).

3. Operações e Métodos (Comportamento)

Uma Operação é a especificação de uma tarefa que pode ser solicitada a um objeto; o Método é a implementação real (o código) dessa operação.

Sintaxe da Operação

A notação completa é:

visibilidade nome (lista_de_parâmetros) : tipo_de_retorno {propriedades}
+ transferirRecursos (in valor : double = 0.0, inout contaDestino : Conta, out protocolo : String) : boolean {leaf}
  • Parâmetros: São informações necessárias para a execução. A sintaxe interna é direção nome : tipo = valor_padrão. As direções podem ser in (entrada), out (saída) ou inout (ambos).
  • Tipo de Retorno: Indica o dado que a operação devolve após a execução (ex: double, void, List).
Tipos de Operações
  • Construtor: Cria uma nova instância da classe (ex: create() ou insert()).
  • Consulta (Query): Obtém informações do estado do objeto sem alterá-lo (sem efeitos colaterais). É marcada com {query}.
  • Atualização (Modifier/Command): Altera os valores dos atributos e o estado do objeto.

4. Definição de Visibilidade

A visibilidade define de onde um recurso (atributo ou método) pode ser acessado dentro da arquitetura do sistema:

Símbolo Tipo Descrição
+ Pública O recurso pode ser acessado por qualquer outra classe no sistema.
- Privada Acesso permitido apenas dentro da própria classe que o define. É o padrão recomendado para atributos para garantir o encapsulamento.
# Protegida Visível apenas para a própria classe e suas subclasses (herança).
~ Pacote Visível por qualquer classe que pertença ao mesmo pacote (namespace).

5. Membros Estáticos e Abstratos

  • Membros Estáticos (Escopo de Classe): São atributos ou operações que pertencem à classe como um todo, e não a um objeto específico. Todas as instâncias compartilham o mesmo valor. Na UML, são representados com o texto sublinhado.
  • Membros Abstratos: Uma operação abstrata possui apenas a assinatura, sem implementação, obrigando as subclasses a implementarem o comportamento. Representados em itálico.

Exemplo Prático

Exemplo 1: O Clássico Sistema de Cadastro (Nível Básico)

Este exemplo introduz a anatomia de uma classe: o nome, os atributos (com tipos de dados) e os métodos (funções).

classDiagram class Usuario { +int id +String nome +String email -String senha +cadastrar() bool +alterarSenha(novaSenha) void }
Código de Implementação (PHP):
<?php

class Usuario {
    // Atributos Públicos (+) e Privados (-)
    public int $id;
    public string $nome;
    public string $email;
    private string $senha;

    public function __construct(int $id, string $nome, string $email, string $senha) {
        $this->id = $id;
        $this->nome = $nome;
        $this->email = $email;
        $this->senha = $senha; // Encapsulado internamente
    }

    // Métodos Públicos (+)
    public function cadastrar(): bool {
        // Lógica para salvar no banco de dados
        echo "Usuário {$this->nome} cadastrado com sucesso!\n";
        return true;
    }

    public function alterarSenha(string $novaSenha): void {
        $this->senha = password_hash($novaSenha, PASSWORD_BCRYPT);
        echo "Senha alterada com segurança.\n";
    }
}
Explicação Didática:
  • Visibilidade: O símbolo + indica que o atributo/método é público (qualquer um acessa). O símbolo - indica que é privado (apenas a própria classe lê ou altera, aplicando o conceito de Encapsulamento).
  • Tipos e Retornos: Mostra claramente o tipo da variável (String, int) e o que o método devolve após ser executado (bool, void).

Exemplo 2: Herança em um Sistema de E-commerce (Nível Intermediário)

Aqui demonstramos o conceito de especialização/generalização ("é um").

classDiagram class Produto { +int codigo +String nome +float preco +exibirDetalhes() } class Livro { +String autor +String isbn } class Eletronico { +int voltagem +String marca } Produto <|-- Livro : é um tipo de Produto <|-- Eletronico : é um tipo de
Código de Implementação (PHP):
<?php

class Produto {
    public int $codigo;
    public string $nome;
    public float $preco;

    public function __construct(int $codigo, string $nome, float $preco) {
        $this->codigo = $codigo;
        $this->nome = $nome;
        $this->preco = $preco;
    }

    public function exibirDetalhes(): void {
        echo "Produto: {$this->nome} - R$ {$this->preco}\n";
    }
}

// Livro herda (<|--) de Produto
class Livro extends Produto {
    public string $autor;
    public string $isbn;

    public function __construct(int $codigo, string $nome, float $preco, string $autor, string $isbn) {
        parent::__construct($codigo, $nome, $preco); // Reaproveita o construtor pai
        $this->autor = $autor;
        $this->isbn = $isbn;
    }
}

// Eletronico herda (<|--) de Produto
class Eletronico extends Produto {
    public int $voltagem;
    public string $marca;

    public function __construct(int $codigo, string $nome, float $preco, int $voltagem, string $marca) {
        parent::__construct($codigo, $nome, $preco);
        $this->voltagem = $voltagem;
        $this->marca = $marca;
    }
}
Explicação Didática:
  • Seta <|--: Representa a herança. A seta aponta sempre da subclasse (filho) para a superclasse (pai).
  • Reutilização: Livro e Eletronico herdam automaticamente os atributos codigo, nome e preco, sem precisar reescrevê-los.

Exemplo 3: Associação com Multiplicidade (Sistema de Clínica Médica)

Este exemplo mostra como duas classes independentes se relacionam e quantas instâncias participam dessa relação.

classDiagram class Medico { +String crm +String nome } class Paciente { +String cpf +String nome } Medico "1" --> "0..*" Paciente : atende
Código de Implementação (PHP):
<?php

class Paciente {
    public string $cpf;
    public string $nome;

    public function __construct(string $cpf, string $nome) {
        $this->cpf = $cpf;
        $this->nome = $nome;
    }
}

class Medico {
    public string $crm;
    public string $nome;
    public array $pacientes = []; // Guarda a coleção de 0..* pacientes

    public function __construct(string $crm, string $nome) {
        $this->crm = $crm;
        $this->nome = $nome;
    }

    // Método que materializa a associação "atende"
    public function atenderPaciente(Paciente $paciente): void {
        $this->pacientes[] = $paciente;
        echo "Médico {$this->nome} está atendendo o paciente {$paciente->nome}.\n";
    }
}
Explicação Didática:
  • Multiplicidade ("1" e "0..*"): Indica as regras de negócio. Neste cenário, um (1) médico específico pode atender de zero a vários (0..*) pacientes.
  • Navegabilidade (-->): A seta indica o sentido da associação (o médico possui uma lista de pacientes ou sabe quem está atendendo).

Exemplo 4: Agregação vs. Composição (Sistema de Computador)

Colocá-los lado a lado no mesmo diagrama ajuda a fixar a diferença de dependência de ciclo de vida.

classDiagram class Computador { +String marca } class Processador { +String modelo +float frequencia } class Mouse { +String tipo } Computador "1" *-- "1" Processador : composição (obrigatório) Computador "1" o-- "0..1" Mouse : agregação (opcional)
Código de Implementação (PHP):
<?php

class Processador {
    public string $modelo;
    public function __construct(string $modelo) { $this->modelo = $modelo; }
}

class Mouse {
    public string $tipo;
    public function __construct(string $tipo) { $this->tipo = $tipo; }
}

class Computador {
    public string $marca;
    public Processador $processador; // Parte da Composição
    public ?Mouse $mouse = null;     // Parte da Agregação (Pode ser nulo)

    public function __construct(string $marca, string $modeloProcessador) {
        $this->marca = $marca;
        // COMPOSIÇÃO: O Processador nasce obrigatoriamente JUNTO com o Computador.
        // Se o objeto Computador for destruído, este Processador morre junto.
        $this->processador = new Processador($modeloProcessador);
    }

    // AGREGAÇÃO: O Mouse é criado FORA e apenas acoplado ao computador.
    // Se o Computador for destruído, o objeto Mouse continua existindo na memória.
    public function conectarMouse(Mouse $mouse): void {
        $this->mouse = $mouse;
    }
}
Explicação Didática:
  • Composição (Losango Preenchido *--): O Processador é parte essencial do Computador. Se o computador for destruído, o processador deixa de existir no contexto do sistema. A relação é de dependência existencial.
  • Agregação (Losango Vazio o--): O Mouse é apenas conectado ao Computador. Se o computador quebrar ou for excluído, o mouse continua existindo de forma independente e pode ser associado a outro computador.

Exemplo 5: O Cenário Completo (Padrão Apostila)

Para fechar o conteúdo, um diagrama que une a maioria dos conceitos em um ecossistema escolar (ideal para bater com os exemplos de Casos de Uso).

classDiagram class Pessoa { <<abstract>> +String nome +String email } class Professor { +String siape +postarMaterial() } class Aluno { +String matricula +entregarTarefa() } class Disciplina { +String nome +int cargaHoraria } class Turma { +String codigo +gerarDiario() } Pessoa <|-- Professor Pessoa <|-- Aluno Professor "1" --> "*" Disciplina : leciona Turma "1" *-- "*" Aluno : composta por Turma "*" o-- "1" Disciplina : pertence a
Código de Implementação (PHP):
<?php

// Classe Abstrata base
abstract class Pessoa {
    public string $nome;
    public string $email;

    public function __construct(string $nome, string $email) {
        $this->nome = $nome;
        $this->email = $email;
    }
}

class Disciplina {
    public string $nome;
    public function __construct(string $nome) { $this->nome = $nome; }
}

// Professor herda de Pessoa e se associa a Disciplinas
class Professor extends Pessoa {
    public string $siape;
    public array $disciplinas = [];

    public function __construct(string $nome, string $email, string $siape) {
        parent::__construct($nome, $email);
        $this->siape = $siape;
    }

    public function lecionarDisciplina(Disciplina $disciplina): void {
        $this->disciplinas[] = $disciplina;
    }

    public function postarMaterial(): void {
        echo "{$this->nome} postou um novo PDF de aula.\n";
    }
}

class Aluno extends Pessoa {
    public string $matricula;

    public function __construct(string $nome, string $email, string $matricula) {
        parent::__construct($nome, $email);
        $this->matricula = $matricula;
    }

    public function entregarTarefa(): void {
        echo "{$this->nome} enviou o arquivo da tarefa.\n";
    }
}

// Turma compõe Alunos e agrega uma Disciplina
class Turma {
    public string $codigo;
    public Disciplina $disciplina; // Agregação (A disciplina existe fora da turma)
    public array $alunos = [];      // Composição conceitual dos alunos nesta grade

    public function __construct(string $codigo, Disciplina $disciplina) {
        $this->codigo = $codigo;
        $this->disciplina = $disciplina;
    }

    public function matricularAluno(Aluno $aluno): void {
        $this->alunos[] = $aluno;
    }
}
Explicação Didática:
  • <<abstract>>: Indica que Pessoa é uma classe abstrata (um conceito, uma interface) e não pode ser instanciada diretamente, apenas herdada por Professor e Aluno.
  • Leitura de Fluxo: Mostra como o sistema mapeia a escola: Uma Turma é composta obrigatoriamente por vários Alunos (se a turma sumir, o agrupamento de alunos some), mas a Disciplina vinculada à turma é uma agregação (a disciplina Matemática continua existindo na grade curricular mesmo se aquela turma fechar).

Dicas & Lembretes

Anatomia de uma Classe

Uma classe é representada graficamente por um retângulo dividido em três secções principais: o nome da classe, os seus atributos e os seus métodos.

  • Sinais de Visibilidade:
    • + (Público): Permite que qualquer outra classe do sistema aceda e altere o elemento.
    • - (Privado): Restringe o acesso e a modificação exclusivamente à própria classe. Este sinal fundamenta a aplicação do conceito de Encapsulamento.
  • Sintaxe de Notação: A ordem padrão de declaração define primeiro o identificador do elemento e, em seguida, o seu tipo de dado ou retorno.
    • Exemplo de atributo: nome: String
    • Exemplo de método: calcularTotal(): float
Orientação e Sentido dos Relacionamentos

A convenção gráfica da UML determina uma regra fixa para o desenho das ligações: A ponta da seta aponta sempre na direção do elemento mais forte, mais genérico ou da classe base (superclasse).

  • Herança (Generalização): Indica uma relação estrutural de "é um". É representada por uma linha contínua com uma seta de ponta triangular vazia na extremidade (<|--). No código fonte em PHP, este relacionamento traduz-se pelo uso da palavra-chave extends.
  • Dependência: Indica uma relação de utilização temporária ("usa um"). É representada por uma linha tracejada com uma seta simples na ponta. Significa que uma classe utiliza instâncias de outra classe apenas como parâmetros locais dentro de um método, sem armazená-las como propriedades fixas.
Distinção entre Agregação e Composição

Ambos os relacionamentos especificam uma associação do tipo "tem um", contudo possuem regras distintas no que diz respeito ao ciclo de vida dos objetos envolvidos.

  • Agregação (Linha com losango vazio na ponta o--): Caracteriza um vínculo onde o "Todo" possui a "Parte", mas a "Parte" pode existir de maneira autónoma. Caso o objeto principal ("Todo") seja excluído ou destruído no sistema, o objeto secundário ("Parte") permanece preservado na memória.
    • Exemplo: Um Computador possui um Mouse. A destruição do objeto computador não extingue o objeto mouse, que pode ser associado a outra máquina.
  • Composição (Linha com losango preenchido na ponta *--): Caracteriza um vínculo de forte dependência existencial. A "Parte" não possui autonomia. Se o objeto principal ("Todo") for eliminado do sistema, todos os objetos dependentes ("Partes") que o constituem são destruídos em simultâneo.
    • Exemplo: Um Computador possui um Processador. Se o computador deixar de existir no sistema, o processador integrado perde o sentido contextual e é destruído conjuntamente.
Multiplicidade

A multiplicidade define as regras de negócio em relação ao número de instâncias que podem participar ativamente numa associação. A leitura da multiplicidade deve ser feita sempre direcionando o olhar para a extremidade oposta da linha de relacionamento.

  • 1: Exatamente uma instância.
  • 0..* ou *: Zero ou várias instâncias.
  • 1..*: No mínimo uma instância, sem limite superior.
Equivalência no Código Fonte

Sempre que o diagrama de classes indicar uma Associação, Agregação ou Composição entre uma Classe A e uma Classe B, a implementação prática exige que a Classe A possua um atributo interno estruturado para armazenar o objeto (ou um vetor/array de objetos) pertencente à Classe B.
