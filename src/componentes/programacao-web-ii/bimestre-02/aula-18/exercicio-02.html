1. Descrição do Projeto

Você foi contratado para desenvolver o motor (back-end) de uma nova Fintech de organização pessoal: o MyPocket. O objetivo deste projeto é aplicar os conceitos de Programação Orientada a Objetos para gerenciar o saldo, receitas e despesas de um usuário de forma segura e organizada.

Diferente de scripts comuns, o MyPocket deve garantir que o saldo nunca seja alterado sem passar por uma validação e que o histórico de transações seja preservado através de instâncias de objetos.

2. Requisitos Técnicos (O que será avaliado)

  • Encapsulamento Rigoroso: O saldo da carteira deve ser private. Nenhuma classe externa pode fazer $carteira->saldo = 1000.
  • Herança e Abstração: Deve existir uma classe abstrata Transacao que sirva de molde para as classes Receita e Despesa.
  • Métodos Mágicos: Uso do __construct para garantir que toda transação nasça com valor, data e descrição.
  • Tratamento de Exceções: Implementação de try/catch para impedir que o usuário lance uma despesa maior que o saldo disponível.
  • Polimorfismo: Cada tipo de transação deve saber identificar se é uma "Entrada" ou "Saída" através de um método comum.

3. Estrutura de Arquivos Sugerida

/mypocket
  ├── classes/
  │    ├── Transacao.php  (Classe Abstrata)
  │    ├── Receita.php    (Extende Transacao)
  │    ├── Despesa.php    (Extende Transacao)
  │    └── Carteira.php   (Gerencia o saldo e a coleção de objetos)
  ├── processa.php        (Captura o formulário e manipula os objetos)
  └── index.php           (Interface visual em Bootstrap)

4. O Desafio Prático

Seu sistema deve ser capaz de:

  1. Cadastrar uma Receita (ex: Salário) que aumenta o saldo da Carteira.
  2. Cadastrar uma Despesa (ex: Aluguel) que diminui o saldo da Carteira.
  3. Impedir o Saldo Negativo: Caso o usuário tente cadastrar uma despesa de R$ 500,00 tendo apenas R$ 200,00 de saldo, a classe Carteira deve disparar uma Exception.
  4. Exibir Extrato: Listar todas as transações realizadas, indicando com cores (verde para receitas, vermelho para despesas) a origem de cada valor.

5. Desafios Bônus Opcional

Para os alunos que quiserem ir além, propomos as seguintes melhorias na aplicação:

  • Exportar Extrato: Criar uma funcionalidade que permite baixar as transações no formato .csv.
  • Filtro de Dados: Implementar filtros na interface para visualizar apenas "Despesas" ou transações de um mês específico.

Orientações de Entrega

  • Tipagem Estrita: Utilize declare(strict_types=1); em todos os arquivos de classe.
  • Single Responsibility: Lembre-se que a classe Transacao cuida do dado, enquanto a Carteira cuida da lógica do dinheiro.
  • Boas Práticas: Utilize nomes de métodos em camelCase e nomes de classes em PascalCase.
  • Teste de Fogo: O projeto será validado tentando burlar o saldo via código e forçando erros de limite para testar o try/catch.
