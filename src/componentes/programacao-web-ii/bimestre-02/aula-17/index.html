Teoria & Conceitos

O tratamento de exceções é um mecanismo que permite ao código lidar com problemas de execução de forma estruturada. Em vez de simplesmente interromper o script com uma mensagem de erro "feia", o desenvolvedor pode capturar o erro, tratá-lo e decidir se o programa deve continuar ou falhar graciosamente.

1. O que são Exceções?

Uma exceção é um objeto especial instanciado a partir da classe integrada Exception (ou de uma classe derivada). Enquanto os erros tradicionais do PHP (como notices ou warnings) são gerados pelo motor da linguagem, as exceções são disparadas manualmente pelo programador quando uma condição inesperada ocorre.

A diferença entre Erros e Exceções

  • Erros: Geralmente indicam falhas fatais no script ou problemas de sintaxe que o PHP detecta automaticamente.
  • Exceções: São utilizadas para situações que você sabe que podem ocorrer em circunstâncias excepcionais (como um arquivo que não abre ou uma conexão de rede que falha).

2. A Estrutura try, catch e finally

Para gerenciar exceções, o PHP utiliza um bloco de controle dividido em três partes:

  • O bloco try (Tentar): Você envolve o código propenso a erros dentro deste bloco. Ele diz ao PHP: "Tente executar este código; se algo der errado, eu tenho um plano".
  • O bloco catch (Capturar): Se uma exceção for disparada dentro do try, a execução é interrompida imediatamente e o controle salta para o catch. Este bloco recebe o objeto de exceção como um argumento, permitindo acessar detalhes do erro.
  • O bloco finally (Finalmente): Introduzido no PHP 5.5, este bloco é executado sempre, independentemente de ter ocorrido uma exceção ou não. É ideal para "limpar a bagunça", como fechar conexões de banco de dados ou liberar recursos de arquivos que não podem ficar abertos.

Exemplo Prático: Fluxo Básico

<?php
try {
    echo "Iniciando processo...\n";
    // Simulando um erro: divisão por zero ou função inexistente
    if (!file_exists("config.txt")) {
        throw new Exception("Arquivo de configuração não encontrado!");
    }
} catch (Exception $e) {
    // O catch captura o objeto lançado pelo 'throw'
    echo "Erro capturado: " . $e->getMessage() . "\n";
} finally {
    // Este código roda ocorrendo erro ou não
    echo "Finalizando limpeza de recursos.\n";
}
?>

3. Disparando Exceções com throw

A palavra-chave throw é usada para sinalizar que um erro ocorreu. Ela exige um objeto, geralmente uma instância da classe Exception, que aceita dois parâmetros opcionais: uma mensagem (string) e um código de erro (inteiro).

4. A Classe Integrada Exception

Ao capturar uma exceção, você tem acesso a métodos úteis para diagnóstico:

  • getMessage(): Retorna a mensagem de erro passada ao construtor.
  • getCode(): Retorna o código numérico do erro.
  • getFile(): Retorna o caminho completo do arquivo onde o erro ocorreu.
  • getLine(): Retorna o número da linha da falha.
  • getTraceAsString(): Fornece o "rastro" (stack trace) das funções que levaram ao erro, essencial para depuração.

5. Exceções Customizadas (Subclassing)

Uma das maiores vantagens da Orientação a Objetos é a possibilidade de criar suas próprias categorias de erro estendendo a classe Exception. Isso permite o Selective Catching (captura seletiva), onde você trata erros diferentes de formas diferentes.

Exemplo Prático: Exceções Customizadas

Imagine um sistema que lida com conexões de banco de dados e arquivos. Você pode criar classes específicas para cada um: 

<?php
// Definindo exceções customizadas
class BancoDadosException extends Exception {}
class ArquivoNaoEncontradoException extends Exception {}

class Logger {
    public function salvarLog($msg) {
        // Lógica de negócio...
        if (rand(0, 1)) { // Simulando falha aleatória
            throw new BancoDadosException("Falha ao gravar no banco!");
        }
        throw new ArquivoNaoEncontradoException("Caminho do log inválido.");
    }
}

// Uso com múltiplos blocos catch
try {
    $log = new Logger();
    $log->salvarLog("Acesso de usuário");
} catch (BancoDadosException $e) {
    echo "Ação: Tentar reconectar ao banco. Erro: " . $e->getMessage();
} catch (ArquivoNaoEncontradoException $e) {
    echo "Ação: Criar diretório e tentar novamente. Erro: " . $e->getMessage();
} catch (Exception $e) {
    echo "Erro genérico: " . $e->getMessage();
}
?>

Regra de Ouro: Ao usar múltiplos blocos catch, sempre coloque as exceções mais específicas primeiro e a genérica (Exception) por último, como um "redutor de danos" (backstop).

6. Boas Práticas e Lembretes

  • Não use Exceções para Fluxo Normal: Exceções devem ser reservadas para circunstâncias excepcionais, não para a lógica comum do dia a dia (como um if/else).
  • Evite o "Blanket Catch": Nunca capture uma exceção genérica e a ignore (ficar em silêncio). Isso esconde bugs reais e dificulta muito a manutenção.
  • Hierarquia de Tipos: O PHP 7+ introduziu a interface Throwable, que é a base tanto para Exception quanto para a classe Error (erros internos do PHP), permitindo capturar quase tudo o que pode dar errado no sistema.

Exemplo de Código

1. Nível Básico: O Bloco try/catch Tradicional

O objetivo deste exemplo é demonstrar o fluxo de interrupção: quando o código falha, o PHP interrompe a execução do bloco try e desvia imediatamente para o catch. 

<?php
declare(strict_types=1);

function validarIdade(int $idade): bool {
    if ($idade < 18) {
        // O throw funciona como uma interrupção da função, disparando a exceção
        throw new Exception("Acesso negado: O utilizador deve ser maior de idade.");
    }
    return true;
}

// Fluxo de teste
try {
    echo "Iniciando verificação...<br>";
    
    validarIdade(15); // Isto vai lançar a exceção
    
    echo "Esta linha NUNCA será executada se a idade for menor que 18.<br>";

} catch (Exception $e) {
    // Captura o objeto da exceção e extrai a mensagem contida nele
    echo "Erro capturado: " . $e->getMessage() . "<br>";
}

echo "O script continua a executar normalmente daqui para baixo por causa do catch!";
?>

2. Nível Intermediário: Multi-catch (Múltiplas Exceções)

Este exemplo demonstra que um único bloco try pode disparar alarmes diferentes, permitindo que o sistema reaja de forma personalizada para cada tipo de problema. 

<?php
declare(strict_types=1);

class ConversorCamadas {
    public function processarUpload(array $arquivo, int $tamanhoMaximo): void {
        if (!isset($arquivo['extensao']) || $arquivo['extensao'] !== 'mp3') {
            // Lançando uma exceção nativa do PHP para argumentos inválidos
            throw new InvalidArgumentException("Formato de arquivo inválido. Apenas MP3 é aceite.");
        }

        if ($arquivo['tamanho'] > $tamanhoMaximo) {
            // Lançando uma exceção nativa do PHP para limites estourados
            throw new LengthException("O arquivo excede o limite máximo permitido de {$tamanhoMaximo} bytes.");
        }

        echo "Arquivo processado com sucesso!<br>";
    }
}

// Fluxo de teste no Controller (processa.php)
$conversor = new ConversorCamadas();
$meuArquivo = ['extensao' => 'exe', 'tamanho' => 5000];

try {
    $conversor->processarUpload($meuArquivo, 2000);

} catch (InvalidArgumentException $e) {
    // Resposta específica para o formato do arquivo
    echo "Erro de Formato: " . $e->getMessage();

} catch (LengthException $e) {
    // Resposta específica para o tamanho do arquivo
    echo "Erro de Limite: " . $e->getMessage();

} catch (Exception $e) {
    // Proteção genérica para qualquer outro erro inesperado
    echo "Erro desconhecido: " . $e->getMessage();
}
?>

3. Nível Avançado: Exceções Customizadas de Domínio com Herança

Este exemplo aborda a criação de classes de exceção próprias estendendo a classe Exception nativa do PHP. Isto permite isolar as regras de negócio baseadas no domínio do projeto. 

<?php
declare(strict_types=1);

// 1. Definição das Exceções do Domínio Financeiro (Herança de Exception)
class TransacaoException extends Exception {}
class SaldoInsuficienteException extends TransacaoException {}
class LimiteDiarioExcedidoException extends TransacaoException {}

// 2. Regra de Negócio usando as Exceções Customizadas
class ContaBancaria {
    private float $saldo = 100.00;
    private float $limiteMaximoSaque = 500.00;

    public function sacar(float $valor): void {
        if ($valor > $this->limiteMaximoSaque) {
            throw new LimiteDiarioExcedidoException("O limite máximo por saque é de R$ {$this->limiteMaximoSaque}.");
        }

        if ($valor > $this->saldo) {
            throw new SaldoInsuficienteException("Saldo insuficiente. Saldo atual: R$ {$this->saldo}.");
        }

        $this->saldo -= $valor;
        echo "Saque de R$ {$valor} realizado!<br>";
    }
}

// 3. Aplicação Prática e captura hierárquica
$conta = new ContaBancaria();

try {
    $conta->sacar(600.00); 

} catch (SaldoInsuficienteException $e) {
    // Trata especificamente a falta de saldo
    echo "Banco: " . $e->getMessage();

} catch (LimiteDiarioExcedidoException $e) {
    // Trata especificamente a segurança de limite do caixa eletrônico
    echo "Segurança: " . $e->getMessage();

} catch (TransacaoException $e) {
    // Captura QUALQUER exceção que seja filha de TransacaoException
    echo "Erro na transação financeira: " . $e->getMessage();
}
?>

4. Nível Profissional: O Bloco finally e Libertação de Recursos

Demonstração do uso do bloco finally, que executa obrigatoriamente, ocorrendo um erro ou não. É utilizado para fechar conexões de banco de dados ou libertar arquivos abertos na memória do servidor. 

<?php
declare(strict_types=1);

class GerenciadorArquivo {
    public function lerDadosConfiguracao(string $caminho): void {
        echo "Abrindo conexão com o arquivo físico...<br>";
        $arquivoAberto = true; // Simula o arquivo travado na memória do servidor

        try {
            if (!file_exists($caminho)) {
                throw new RuntimeException("O arquivo de configuração solicitado não existe.");
            }
            
            echo "Lendo dados...<br>";

        } catch (RuntimeException $e) {
            echo "Tratando erro interno: " . $e->getMessage() . "<br>";
            
        } finally {
            // O FINALLY garante que o arquivo seja fechado independentemente do erro
            $arquivoAberto = false;
            echo "Bloco Finally Executado: Arquivo fechado com segurança e memória libertada.<br>";
        }
    }
}

// Teste
$gerenciador = new GerenciadorArquivo();
$gerenciador->lerDadosConfiguracao("config.json"); // Força o erro porque o arquivo não existe
?>
